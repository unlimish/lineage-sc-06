# 03. ビルド手順 — LineageOS 16.0 (Android 9) for SC-06D

**注意: この手順は実機・実ビルドで検証していません。** 一次情報（各リポジトリの
存在とブランチ）は確認済みですが、初回ビルドではエラーが出るものと考えてください。
詰まったところは [`05-ワンセグ移植の手順.md`](05-ワンセグ移植の手順.md) の考え方が
そのまま使えます。

---

## 1. 必要なもの

| 項目 | 必要量 | 備考 |
|---|---|---|
| ディスク | **110〜130GB**（下記参照） | 浅いクローン前提。160GB あれば足りる |
| RAM | 8GB 以上 | 16GB あると快適 |
| CPU | 4コア以上 | 4コアで初回 4〜8時間 |
| OS | Ubuntu 18.04 / 20.04 | **これが重要。次項参照** |
| Python | **2.7 が必要** | LineageOS 16.0 のビルド系は Python 2 前提 |

### ディスクの内訳

初版でここに「300GB前後」と書いていましたが、**余裕を見すぎた数字**でした。
実際の内訳はおおむねこうなります。

| | 目安 |
|---|---|
| ソース（`--depth=1` の浅いクローン） | **約 60GB**（実測） |
| `out/`（1機種ぶん） | 40〜60GB |
| ccache（任意） | 0〜10GB |
| **合計** | **約 100〜130GB** |

ソースの 60GB は実測値です（`.repo` が 15GB、残りが作業ツリー）。
同期直後に `df -h .` を見て、**`out/` のぶんが残っているか**を確認してください。

**160GB 程度あれば通る見込みです。** ただし余裕は多くないので、下の節約策を
最初から適用してください。履歴を全部引くと数百GBになるので、
`--depth=1` は「あると良い」ではなく**必須**です。

### ディスクを節約する

```bash
# 1. 浅いクローン + 現在のブランチのみ（最大の効き目）
repo init -u https://github.com/LineageOS/android.git -b lineage-16.0 \
    --depth=1 --no-clone-bundle
repo sync -c -j4 --no-clone-bundle --no-tags --force-sync

# 2. ccache は使うなら上限を切る（使わなくてもビルドは通る）
export USE_CCACHE=1 CCACHE_DIR=/srv/ccache
ccache -M 10G

# 3. 進行中に見張る
df -h .          # 残り
du -sh .repo out # 内訳
```

`repo sync` の途中で容量が尽きると中途半端な状態になります。
**同期が終わった時点で `du -sh .repo` を確認**して、
残りが `out/` に足りるかを見てから `mka` に進んでください。

### ビルドせずに済む確認を先にやる

LineageOS 16.0 のビルドは数時間かかります。その前に、
**ビルドしなくても答えが出る問い**を片付けておくと無駄が減ります。

残っている最大の未知は「純正の 3 つの .so が Android 9 の linker で
ロードできるか」ですが、これは**静的に判定できます**。

```bash
# Android 9 (ARM 32bit) の system/lib があれば
python3 tools/analyze-oneseg-blobs.py oneseg-report/ --against /path/to/android9/system/lib
```

DT_NEEDED と未定義シンボルを全部突き合わせて、
**解決しないものがあれば名前を挙げます**。数秒で終わります。

`system/lib` の入手先としては、**d2att 向けの LineageOS 16.0 ビルド済み zip**
が理想です（同じ MSM8960、同じ Android バージョン）。zip は block-based OTA
形式なので `sdat2img` などで `system.img` に戻してからマウントして取り出します。
数百MB の作業で済み、163GB を使う前に見通しが立ちます。

### ホスト OS について

LineageOS 16.0（2018〜2020年）のビルド環境は、現代の Ubuntu では動きません。
`repo` が Python 2 を要求し、`libncurses5` など今は消えたパッケージに依存します。

**Docker / Podman を強く勧めます。**

```bash
docker run -it --name lineage16 \
    -v "$PWD/lineage:/srv/lineage" \
    -v "$PWD/ccache:/srv/ccache" \
    ubuntu:18.04 /bin/bash
```

以降はコンテナの中で作業します。

## 2. ビルド環境の準備

```bash
apt update && apt install -y \
    bc bison build-essential ccache curl flex g++-multilib gcc-multilib \
    git gnupg gperf imagemagick lib32ncurses5-dev lib32readline-dev \
    lib32z1-dev liblz4-tool libncurses5 libncurses5-dev libsdl1.2-dev \
    libssl-dev libxml2 libxml2-utils lzop pngcrush rsync schedtool \
    squashfs-tools xsltproc zip zlib1g-dev python python-minimal \
    openjdk-8-jdk unzip wget git-lfs

# git-lfs is not optional. external/chromium-webview/prebuilt/* is stored in
# Git LFS, and without it repo sync gets to 99% and then fails those four
# projects with:
#
#   git-lfs filter-process --skip: 1: git-lfs: not found
#   fatal: the remote end hung up unexpectedly
#   error: Unable to fully sync the tree
git lfs install

# repo refuses to init without a committer identity, and the failure is a
# Python traceback rather than a clear message:
#
#   git_command.GitCommandError: 'var GIT_COMMITTER_IDENT' on manifests failed
#   stderr: Committer identity unknown
git config --global user.name  "Your Name"
git config --global user.email "you@example.com"

# repo
mkdir -p ~/bin && export PATH=~/bin:$PATH
curl https://storage.googleapis.com/git-repo-downloads/repo > ~/bin/repo
chmod a+x ~/bin/repo

# ccache は初回以降のビルドを大幅に速くします
export USE_CCACHE=1
export CCACHE_DIR=/srv/ccache
ccache -M 50G
```

`openjdk-8-jdk` である点に注意してください。**Android 9 のビルドは JDK 8 が必須**です。
JDK 11 以降では通りません。

## 3. ソースの取得

### ディレクトリ構成 — `repo init` はこのリポジトリの「外」で

**`repo init` を `lineage-sc-06` の中で実行しないでください。**

`repo` は `.repo/` と数百個の git リポジトリを展開します。
このプロジェクト自体も git リポジトリなので、中で実行すると
**両者が入れ子になって収拾がつかなくなります**
（`git status` が数万ファイルを未追跡として並べる状態）。

2 つを並べて置きます。

```
~/lineage-sc-06/          ← このリポジトリ（ドキュメント・ツール・デバイスツリー）
  device/samsung/d2dcm/
  tools/
  oneseg-report/          ← 実機調査の結果

~/lineage/                ← LineageOS のソース（repo init はここ）
  .repo/
  build/  frameworks/  device/  kernel/  ...
  device/samsung/d2dcm   → ~/lineage-sc-06/device/samsung/d2dcm へのシンボリックリンク
```

**別のディスク／パーティションに置いても構いません。**
むしろ容量に余裕がないなら、そのほうが安全です。

### 手順

```bash
# 1. LineageOS 用のディレクトリを、このリポジトリの外に作る
mkdir -p ~/lineage && cd ~/lineage

# 2. 浅いクローンで init（--depth=1 は必須。省くと数百GBになります）
repo init -u https://github.com/LineageOS/android.git -b lineage-16.0 \
    --depth=1 --no-clone-bundle

# 3. sync の前に local_manifest を置く（後からだと取り込まれません）
mkdir -p .repo/local_manifests
cp ~/lineage-sc-06/manifests/local_manifest.xml .repo/local_manifests/d2dcm.xml

# 4. 同期（1〜3時間）
repo sync -c -j4 --no-clone-bundle --no-tags --force-sync

# 5. 容量を確認してから先へ進む
du -sh .repo && df -h .
```

**手順 3 の順序が重要です。** `local_manifest` は `repo sync` の前に置かないと、
d2att・カーネル・qcom-common が取得されません。

### d2dcm デバイスツリーをリンクする

`device/samsung/d2dcm` は `repo` では取得できません
（このプロジェクトリポジトリのサブディレクトリなので、repo がマップできない）。
シンボリックリンクを張ります。

```bash
~/lineage-sc-06/tools/link-device-tree.sh ~/lineage
```

このリポジトリ側を編集すれば、そのまま `~/lineage` のビルドに反映されます。
コピーし直す手順はありません。

### 同期されたか確認

```bash
~/lineage-sc-06/tools/verify-tree.sh ~/lineage
```

## 4. blob の抽出

**実機（SC-06D）を USB で繋いで、root を取った状態**で行います。

```bash
cd ~/lineage
source build/envsetup.sh
lunch lineage_d2dcm-userdebug

~/lineage-sc-06/tools/extract-d2att.sh                    # d2 共通
cd ~/lineage/device/samsung/d2dcm && ./extract-files.sh   # docomo + ワンセグ
```

### d2 共通 blob になぜ専用スクリプトが要るか

`device/samsung/d2att/extract-files.sh` は**動きません**。

```
$DEVICE must be set before including this script!
```

あれは CyanogenMod 時代のスクリプトで、ツリーが `msm8960-common` /
`d2-common` / キャリア別ディレクトリに分かれていた頃のものです。今の
d2att-unified は全部を1つの `proprietary-files.txt` に統合したのに、
スクリプト側は `$PLATFORM_COMMON` `$DEVICE` `$DEVICE_COMMON` `$VENDOR`
を参照したまま、**どこでも代入していません**。環境変数で渡しても、
後半が同じリストを `vendor/samsung/d2gsm`（誰も読まないディレクトリ）に
もう一度展開しにいくので解決しません。

行き先は推測ではなく `device.mk` に書いてあります。

```makefile
$(call inherit-product-if-exists, vendor/samsung/d2-common/d2-common-vendor.mk)
$(call inherit-product-if-exists, vendor/samsung/msm8960-common/msm8960-common-vendor.mk)
```

**`if-exists` が危険なところです。** blob が1つも無くてもビルドは成功し、
グラフィックも音もラジオも無い zip ができあがります。ビルド時には何も
言われません。`verify-tree.sh` がこれを FAIL にする理由です。

`tools/extract-d2att.sh` は `vendor/samsung/msm8960-common` に展開します。
このリポジトリ側に置いてあるのは、`repo sync --force-sync` が
LineageOS ツリー内の変更を元に戻してしまうからです。

先に `lunch` するのは、`extract-files.sh` が `$ANDROID_BUILD_TOP` を見て
ツリーの位置を決めるからです。`lunch` していない場合は明示できます。

```bash
LINEAGE_ROOT=~/lineage ~/lineage/device/samsung/d2dcm/extract-files.sh
```

<details>
<summary><code>Unable to find helper script at .../vendor/cm/build/tools/extract_utils.sh</code>（d2att 側）</summary>

`vendor/cm` は CyanogenMod 時代のパスで、LineageOS 14.1 で `vendor/lineage`
に改名されています。d2att-unified のスクリプトが更新されていないだけで、
同期漏れではありません。

```bash
sed -i 's|vendor/cm/build/tools|vendor/lineage/build/tools|' \
    ~/lineage/device/samsung/d2att/extract-files.sh \
    ~/lineage/device/samsung/d2att/setup-makefiles.sh
```

`repo sync --force-sync` で元に戻るので、再同期したら貼り直してください。
`verify-tree.sh` が検出して同じ sed を出します。
</details>

<details>
<summary><code>!! lib/xxx.so: file not found in source</code> と出る場合</summary>

`proprietary-files.txt` に書いてあるファイルが実機に無い、という意味です。
抽出自体は止まりませんが、**`setup-makefiles.sh` は存在しないファイルにも
ビルドルールを書きます**。放置するとビルドの後半で落ちるので、
`proprietary-files.txt` 側をコメントアウトして抽出をやり直してください。

実機に何があるかは実機に訊くのが確実です。

```bash
adb shell "ls /system/lib/ | grep -i ril"
```

なお `lib/libsec-ril.so` と `app/SPModePushNotifier.apk` は
純正 4.0.4 の SC-06D には**無い**ことを確認済みで、既に外してあります。
</details>

<details>
<summary><code>bash: ./extract-files.sh: 許可がありません</code>（Permission denied）と言われる場合</summary>

上流のデバイスツリーは実行ビットの付け方が揃っていません（`d2att` 側で起きがちです）。
インタプリタ経由で呼べば、ビットに関係なく動きます。

```bash
cd ~/lineage/device/samsung/d2att && bash ./extract-files.sh
```

一度立てておくほうが後が楽です。`extract-files.sh` は最後に
`setup-makefiles.sh` を呼ぶので、**両方**に付けてください。

```bash
chmod +x ~/lineage/device/samsung/d2att/extract-files.sh \
         ~/lineage/device/samsung/d2att/setup-makefiles.sh
```

`chmod +x` しても直らない場合は、ツリーが `noexec` でマウントされています
（ビルドは通りません）。`verify-tree.sh` がこの2つを区別して報告します。
</details>

<details>
<summary><code>Unable to find helper script at .../extract_utils.sh</code> と言われる場合</summary>

d2dcm は**シンボリックリンク**なので、他機種のデバイスツリーが使っている

```bash
ANDROID_ROOT="$MY_DIR"/../../..
```

という書き方が、ここでは通用しません。カーネルはまず
シンボリックリンクを解決してから `..` を適用するので、3つ上がった先が
LineageOS ツリーではなく **`lineage-sc-06` の外**になります。

```console
$ readlink -f device/samsung/d2dcm/../../..
/home/user/lineage-sc-06          ← ~/lineage ではない
```

同梱の `extract-files.sh` はこれを踏まえて、階層を数える代わりに
`vendor/lineage/build/tools/extract_utils.sh` を上に向かって探します。
それでも出る場合は、そのファイルが本当に無い（`vendor/lineage` の同期漏れ）ので、
`verify-tree.sh` が名指しします。
</details>

純正 ROM を展開してあるなら、パスを渡してオフラインでも抽出できます。

```bash
./extract-files.sh /path/to/extracted/stock/rom
```

抽出されたものは `vendor/samsung/` に入ります。**リポジトリにはコミットしないでください。**

## 5. ビルド

```bash
cd ~/lineage
source build/envsetup.sh
lunch lineage_d2dcm-userdebug
mka bacon -j$(nproc)
```

成果物: `out/target/product/d2dcm/lineage-16.0-<日付>-UNOFFICIAL-d2dcm.zip`

### `lunch` が出す警告について

```
Trying dependencies-only mode on a non-existing device tree?
```

**これは正常です。無視してください。** `lunch` は roomservice.py を呼び、
デバイスツリーを LineageOS の GitHub から自動取得しようとします。d2dcm は
このプロジェクト内にあってマニフェストに載っていないので、roomservice には
「無い」ように見えます。

副作用として `lineage.dependencies` も読まれませんが、そこに書かれた
3つ（d2att-unified / qcom-common / kernel）は `local_manifest.xml` が
すべて明示的に取得済みなので、実害はありません。

判定は次の行を見てください。ここが正しければ `lunch` は成功しています。

```
LINEAGE_VERSION=16.0-<日付>-UNOFFICIAL-d2dcm
TARGET_PRODUCT=lineage_d2dcm
TARGET_ARCH=arm
PRODUCT_SOONG_NAMESPACES= hardware/qcom/audio-caf/msm8960 ...
```

最後の `PRODUCT_SOONG_NAMESPACES` に msm8960 が並んでいれば、
d2att-unified の設定まで読み込めています。

### カーネルだけ先に試す

デバイスツリーの調整で手戻りが多いので、**まずカーネルが通るか**を確認すると効率的です。
ワンセグドライバがビルドに含まれるかもここで分かります。

```bash
cd ~/lineage
make -C kernel/samsung/d2 O=out ARCH=arm lineageos_d2dcm_defconfig
grep ISDBT kernel/samsung/d2/out/.config
```

期待する出力:

```
CONFIG_ISDBT_NMI=y
CONFIG_ISDBT_NMI_DEBUG=y
```

**ここで `# CONFIG_ISDBT_NMI is not set` になっていたら、
`TARGET_KERNEL_CONFIG` が `lineageos_d2_defconfig` にすり替わっています。**
`device/samsung/d2dcm/BoardConfig.mk` を確認してください。

## 6. 初回ビルドでよく詰まるところ

### `TARGET_KERNEL_CONFIG` が効いていない

`BoardConfig.mk` は d2att のものを `-include` してから上書きしています。
`-include` の後ろで上書きしているか、順序を確認してください。

### パーティションサイズ超過

```
error: system image is X bytes, limit is Y
```

`BoardConfig.mk` のサイズは d2att（16GB 機）から継承した値で、
**SC-06D（32GB）では合っていません**。実機から取り直してください。

```bash
adb shell su -c 'cat /proc/partitions'
adb shell su -c 'ls -l /dev/block/platform/msm_sdcc.1/by-name/'
```

`tools/oneseg-probe.sh` を実行済みなら `oneseg-report/proc-partitions.txt` にあります。

### blob 不足

```
error: vendor/samsung/d2dcm/... No such file
```

`extract-files.sh` が失敗しているか、`proprietary-files.txt` に
実機に無いファイルが書かれています。純正 ROM のバージョン違いが原因のことが多いです。
無いファイルは行頭に `-` を付けると「任意」扱いになります。

### JDK のバージョン

```
java.lang.UnsupportedClassVersionError
```

JDK 8 になっているか確認: `java -version`

**最初のビルドではワンセグを入れないでください。** まず素の LineageOS 16.0 を
起動させて、`/dev/isdbt` が出ることを確認するのが先です。
