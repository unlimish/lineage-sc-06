# 08. ワンセグ視聴・録画アプリの設計

**方針が決まりました。録画は「受信した TS をそのままファイルに書く」だけにします。**
CPRM は実装しません。

この 1 行が設計全体を決めます。以下はその帰結です。

---

## 1. なぜこれで正しいのか

録画を「TS をそのまま書く」にすると、**視聴と録画が同じデータ経路になります**。

```
チューナ ──► TS バイト列 ──┬──► デコード ──► 画面    （視聴）
                            └──► write()  ──► .ts     （録画）
```

**録画は「すでに手元にあるバイト列を、もう 1 箇所に書く」だけ**です。
再チューニングも再エンコードも要りません。録画開始 = ファイルを開く、
録画停止 = 閉じる。それだけです。

### 迂回しているものは無い

- **受信経路に暗号がありません。** ワンセグは平文で送出されています
  （[`06-調査ログ.md`](06-調査ログ.md) 第11節、独立した 3 出典で確認）。
- **CPRM は Samsung が SD カードの録画に被せていたラッパ**でした
  （`libonesegcprmapi.so`、`/efs/` から鍵を取得）。
  自作アプリはその形式を**そもそも生成しません**。
  平文 `.ts` を書くのは「CPRM を外す」ではなく「最初から付けない」です。

### 知っておくべき 1 点

TS には放送側のコピー制御信号（`digital_copy_control_descriptor`）が乗っています。
ARIB の受信機規定に準拠した**製品**なら従うべきものです。
自分の端末での私的録画と、配布する製品とでは話が別なので、
**配布を考えるならここは見直す点**になります。

## 2. 移植対象が確定した

録画を自前でやると決めたことで、純正から持ち込むものが確定しました。

| | ファイル |
|---|---|
| **持ち込む** | `libonesegdmxdriver.so`, `libonesegutils.so`, `libPGL.so` |
| **持ち込まない** | CPRM (`libonesegcprmapi.so`)、暗号 (`libsdtvcrypto.so`)、純正デマクサ (`libonesegdemux.so`)、共有メモリ (`libsdtvphmem.so`)、プロセス監視、デーモン 2 つ |

**3 ファイル。** `/efs` への依存も消えました
（IMEI のバックアップとしての `/efs` は当然別途必要です）。

## 3. 構成

```
┌──────────────────────────────────────────────────────────┐
│ UI  (Kotlin/Java)                                        │
│   チャンネル選択 / 録画ボタン / SurfaceView               │
└───────────────┬──────────────────────────────────────────┘
                │ JNI
┌───────────────▼──────────────────────────────────────────┐
│ TsSource  (C++, 専用スレッド)                             │
│                                                          │
│   open("/dev/isdbt")                                     │
│   ioctl(POWER_ON) / INTERRUPT_REGISTER / ENABLE          │
│   poll() ──► read() ──► 188 バイト単位の TS               │
│                                                          │
│              ┌──────────┴──────────┐                     │
│              ▼                     ▼                     │
│         RingBuffer            FileSink (録画時のみ)      │
└──────────────┬───────────────────────┬───────────────────┘
               │                       │
       ┌───────▼────────┐      ┌───────▼──────────────────┐
       │ ExoPlayer      │      │ /sdcard/OneSeg/          │
       │  TsExtractor   │      │   20260907_2100_NHK.ts   │
       │  → MediaCodec  │      └──────────────────────────┘
       │  → Surface     │
       └────────────────┘
```

**分岐点は 1 箇所だけ**です。`TsSource` が `read()` したバッファを、
リングバッファに入れると同時に、録画中ならファイルにも `write()` する。

## 4. 視聴側 — TS のデマックスは自分で書かない

**ExoPlayer (media3) を使ってください。** `TsExtractor` が入っています。

自前で PAT/PMT を解析して PES を組み立てると 300 行以上になり、
しかもバグりやすい部分です。ExoPlayer は同じことを実戦投入済みのコードでやります。

```kotlin
// TsSource のリングバッファを ExoPlayer の DataSource として見せる
class OneSegDataSource(private val ring: RingBuffer) : BaseDataSource(true) {
    override fun open(spec: DataSpec): Long { ring.start(); return C.LENGTH_UNSET.toLong() }
    override fun read(buf: ByteArray, off: Int, len: Int): Int = ring.read(buf, off, len)
    override fun getUri(): Uri? = Uri.parse("oneseg://tuner")
    override fun close() { ring.stop() }
}

val player = ExoPlayer.Builder(context)
    .setMediaSourceFactory(
        ProgressiveMediaSource.Factory(
            { OneSegDataSource(ring) },
            DefaultExtractorsFactory()          // TsExtractor がここに含まれる
        )
    )
    .build()
```

### 想定しているコーデック

| | |
|---|---|
| コンテナ | MPEG-2 TS、188 バイト固定長、同期バイト `0x47` |
| 映像 | H.264 Baseline、320×180 程度、15fps |
| 音声 | HE-AAC。**ADTS ではなく LATM/LOAS** で入っているはず |
| ビットレート | 全体で 400kbps 程度 |

音声の LATM は ExoPlayer の `LatmReader` が扱います。
**ただしこれは未検証です。** 最初のキャプチャを PC で `ffprobe` にかけて、
実際のストリーム構成を確認してください（[`05`](05-ワンセグ移植の手順.md) ステップ 7）。

```bash
adb pull /sdcard/OneSeg/xxxx.ts
ffprobe xxxx.ts        # ここで映像/音声のコーデックが確定する
```

**PC で `ffplay` が再生できた時点で、移植は成功しています。**
端末側の再生は、そのあとの実装の話にすぎません。

## 5. 録画側 — 実装はこれだけ

```cpp
// TsSource の読み出しループ。録画は分岐 1 つ。
void TsSource::loop() {
    uint8_t buf[TS_CHUNK];                 // 188 の倍数にしておく

    while (running_) {
        struct pollfd pfd = { fd_, POLLIN, 0 };
        if (poll(&pfd, 1, 1000) <= 0) continue;

        ssize_t n = ::read(fd_, buf, sizeof buf);
        if (n <= 0) continue;

        ring_->write(buf, n);              // 視聴

        int rec = rec_fd_.load();          // 録画（アトミックに読む）
        if (rec >= 0) {
            ssize_t off = 0;
            while (off < n) {              // 部分書き込みを畳む
                ssize_t w = ::write(rec, buf + off, n - off);
                if (w <= 0) { stopRecording(); break; }
                off += w;
            }
        }
    }
}
```

録画の開始と停止:

```cpp
void TsSource::startRecording(const char* path) {
    int fd = ::open(path, O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd < 0) return;
    int old = rec_fd_.exchange(fd);
    if (old >= 0) ::close(old);
}

void TsSource::stopRecording() {
    int fd = rec_fd_.exchange(-1);
    if (fd >= 0) { ::fsync(fd); ::close(fd); }
}
```

### 設計上の注意

- **読み出しスレッドをブロックしない。** SD カードへの `write()` が詰まると
  リングバッファが溢れて映像が飛びます。安いカードで実測して、
  詰まるようなら録画側を別スレッド + 独自キューに分けてください。
- **188 の倍数で書く。** 途中で切れた TS パケットが混ざると、
  後段のプレイヤーが同期を取り直す羽目になります。
- **`.ts` のまま保存する。** 無変換・無劣化で、VLC でも ffmpeg でもそのまま開けます。
  `.mp4` が欲しければ `MediaMuxer` で後から変換すれば済みます。
  受信直後に変換をかけるのは、失敗したときに元が残らないので損です。
- **ファイル名に日時と局名を入れる。** `20260907_2100_NHK.ts` のように。
  EPG が無くても日時だけで十分機能します。

## 6. チューナ制御 —— 確定済み

**実機で動作確認できました**（[`07`](07-実機調査の結果.md) 第2h節）。
`TsSource` はこれで書けます。

```c
/* dlopen して dlsym。C リンケージなのでそのまま取れる */
void *lib = dlopen("/system/lib/libonesegdmxdriver.so", RTLD_NOW);

int (*Init)(void)            = dlsym(lib, "OneSegDrv_Initailze");   /* sic */
int (*ChipState)(void)       = dlsym(lib, "OneSegDrv_CheckChipState");
int (*SetChannel)(int)       = dlsym(lib, "OneSegDrv_SetChannel");
int (*Lock)(void)            = dlsym(lib, "OneSegDrv_CheckChannelLock");
int (*StartChannel)(int)     = dlsym(lib, "oneseg_start_channel");
int (*ReadData)(void*, int)  = dlsym(lib, "OneSegDrv_ReadData");
int (*Release)(void)         = dlsym(lib, "OneSegDrv_ReleaseChannel");
int (*Finalize)(void)        = dlsym(lib, "OneSegDrv_Finalize");

/* 起動 */
Init();                       /* 0 = 成功 */
ChipState();                  /* 1 = 正常 */
SetChannel(27);               /* 物理チャンネル番号。0 = 成功 */
while (!Lock()) sleep(1);     /* 実測 1 秒でロック */
StartChannel(27);             /* ★ これが無いと ReadData が 0 を返し続ける */

/* 読み出しループ */
uint8_t buf[188 * 32];
for (;;) {
    int n = ReadData(buf, sizeof buf);   /* 実測 3008 = 188 × 16 固定 */
    if (n <= 0) { usleep(20 * 1000); continue; }   /* ブロックしないので待つ */
    ring->write(buf, n);                 /* 視聴 */
    if (rec_fd >= 0) write_all(rec_fd, buf, n);    /* 録画 */
}

/* 停止 */
Release();
Finalize();
```

### 実測値

| | |
|---|---|
| 1 回の `ReadData` | **3008 バイト = 188 × 16 パケット**（常に一定） |
| レート | 422 kb/s（10秒で 151 回、448,192 バイト） |
| ロック時間 | 約 1 秒 |
| ブロックするか | **しない**。データが無ければ 0 を返す |

`ReadData` がブロックしないので、**呼び出し側でペースを作る**必要があります。
0 が返ったら 20ms ほど待つ、で十分でした。

### 落とし穴 2 つ

**1. `oneseg_start_channel()` を忘れない。**
チューニング（`SetChannel`）とストリーム開始は**別手順**です。
ロックまで成功していても、これを呼ばないと `ReadData` は 0 を返し続けます。
`OneSegDrv_*` の一式に start が無いので見落としやすい。

**2. `Initailze` と `Singal` は綴りが間違っている。**
Samsung の原文ママです。直すと `dlsym` が失敗します。

### 音声は TS の中にある

`i2s_snd` というシンボルから「音声が別経路かもしれない」と書いていましたが、
**杞憂でした**。`ffprobe` が同じ TS 内に AAC-LC を見つけています。

```
Stream #0:1[0x583]: Audio: aac (LC), 48000 Hz, stereo, 55 kb/s
Stream #0:2[0x581]: Video: h264 (Constrained Baseline), 320x180, 14.99 fps
```

**ExoPlayer に TS をそのまま流せば、映像も音声も出ます。**

### 残る未知は Bionic の ABI 差だけ

ここまで全部 **Android 4.0.4 上**での話です。Android 9 で同じことをするには、
3 つの .so が Pie の linker でロードできる必要があります。
`libonesegdmxdriver.so` の DT_NEEDED は軽い（`libonesegutils` + AOSP の基本ライブラリ）
ので見込みはありますが、**これが次の関門**です。
