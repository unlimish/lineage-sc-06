# 02. ワンセグの構造と壁

SC-06D のワンセグが何でできているか、そして新しい Android で何が足りなくなるか。
**推測ではなく、実際のカーネルソースを読んで確認した内容**です。

---

## 1. ハードウェア

| 項目 | 内容 |
|---|---|
| チューナ | **Newport Media NMI326**（ISDB-T 1seg 用ワンチップチューナ） |
| 接続 | **SPI**（MSM8960 の GSBI8 / QUP、`bus_num = 1`, `chip_select = 0`） |
| SPI クロック | `max_speed_hz = 5,400,000`（コントローラ側の上限は 15,060,000） |
| SPI モード | `SPI_MODE_0` |
| 電源制御 | PMIC(PM8921) GPIO — `PMIC_GPIO_ISDBT_EN`（電源）, `PMIC_GPIO_ISDBT_RST`（リセット） |
| 割り込み | `GPIO_ISDBT_INT`（TLMM GPIO → `MSM_GPIO_TO_INT()`） |
| アンテナ | 伸縮式ロッドアンテナ（本体内蔵） |

`CONFIG_ISDBT_NMI` の **NMI = Newport Media Inc.** です。
Newport Media は 2014年に Atmel に買収され、現在は Microchip 傘下です。
つまり**チップベンダからの新規サポートは期待できません**。

### 電源投入シーケンス（`board-m2_dcm.c` の `isdbt_gpio_on()` より）

```
1. INT / SPI の 4 本を GPIOMUX FUNC_1（SPI 機能）に切り替え
2. ISDBT_EN = 1
3. 50ms 待つ
4. ISDBT_RST = 0
5. 2ms 待つ
6. ISDBT_RST = 1
7. 10ms 待つ
```

このタイミングはドライバではなくボードファイルに書かれています。
**移植時にここを壊すとチューナが応答しません。**

## 2. カーネルドライバ — `drivers/media/nmi326/`

### ファイル構成

```
drivers/media/nmi326/
├── Kconfig               CONFIG_ISDBT_NMI / CONFIG_ISDBT_NMI_DEBUG
├── Makefile              obj-$(CONFIG_ISDBT_NMI) += nmi326.o nmi326_spi_drv.o
├── nmi326.c              キャラクタデバイス本体（約 10KB）
├── nmi326.h              ioctl 定義・構造体
├── nmi326_spi_drv.c      SPI 転送（約 4.8KB）
└── nmi326_spi_drv.h
```

ライセンスは `MODULE_LICENSE("Dual BSD/GPL")`、著作権表示は Samsung Electronics (2012)。
**ソースが公開されているので、ここは自由に扱えます。**

### ユーザー空間から見た顔

```c
#define ISDBT_DEV_NAME   "isdbt"
#define ISDBT_DEV_MAJOR  225
#define ISDBT_DEV_MINOR  0
```

`register_chrdev(225, "isdbt", &isdbt_fops)` で登録される **キャラクタデバイス `/dev/isdbt`** です。
`misc` デバイスではないので、**`/dev/isdbt` のノードは自動では作られません**
（ueventd か init で作る必要があります。後述）。

### ioctl の全リスト

```c
#define IOCTL_MAGIC 't'

IOCTL_ISDBT_POWER_ON                 _IO('t', 0)   // isdbt_gpio_on() を呼ぶ
IOCTL_ISDBT_POWER_OFF                _IO('t', 1)   // isdbt_gpio_off() を呼ぶ
IOCTL_ISDBT_INTERRUPT_REGISTER       _IO('t', 2)
IOCTL_ISDBT_INTERRUPT_UNREGISTER     _IO('t', 3)
IOCTL_ISDBT_INTERRUPT_ENABLE         _IO('t', 4)
IOCTL_ISDBT_INTERRUPT_DISABLE        _IO('t', 5)
IOCTL_ISDBT_INTERRUPT_DONE           _IO('t', 6)
IOCTL_ISDBT_INTERRUPT_HANDLER_START  _IO('t', 7)
```

**これだけです。** 注目してほしいのは、**ここに「チャンネルを合わせる」も「復調する」も
「TS を読む」も無い**ことです。あるのは電源と割り込み管理だけ。

残りは `read()` / `write()` / `poll()` / `fasync` で、
**SPI バスの生のバイト列をユーザー空間に素通しするだけ**の実装になっています。

### つまりドライバは「穴」でしかない

```
ユーザー空間の .so  ──write()──▶  /dev/isdbt  ──SPI──▶  NMI326
                    ◀──read()───              ◀──────
                    ◀──poll()/SIGIO──  IRQ
```

NMI326 のレジスタマップ、ファームウェアのロード手順、チューニング手順、
TS の取り出し方 —— **プロトコルの知識は 100% ユーザー空間側にあります**。
そしてそれは公開されていません。

これが「カーネルドライバがあるのに移植できない」理由です。

## 3. ユーザー空間 — ここが欠けている

純正 SC-06D の `/system` には、おおむね次の層があるはずです
（**正確なファイル名は実機で `tools/oneseg-probe.sh` を実行して確認してください**。
このリポジトリでは実機で未確認です）。

| 層 | 役割 | 想定される所在 |
|---|---|---|
| アプリ | UI、番組表、録画 | `/system/app/` の Samsung / docomo 製 apk |
| Java フレームワーク | アプリ ↔ ネイティブの橋渡し | `/system/framework/` の jar、`/system/etc/permissions/` の xml |
| ネイティブサービス | 常駐デーモン | `/system/bin/` |
| ミドルウェア | TS 処理、EPG、字幕、**RMP 復号** | `/system/lib/` の .so |
| チューナ制御 | NMI326 のレジスタを叩く | `/system/lib/` の .so |
| ファームウェア | NMI326 にロードするバイナリ | `/system/etc/firmware/` あたり |
| 鍵 | **RMP 鍵** | 不明（`/efs`、隠しパーティション、チップ内 OTP のいずれか） |

### 過去の移植に含まれていないという事実

CM13 の d2dcm デバイスツリーの blob リストには、
RIL・FeliCa・docomo 絵文字は入っているのに、**ワンセグ関連が 1 件もありません**。

FeliCa という難物を移植した人たちが手を出していない。
これは「気づかなかった」ではなく「通らなかった」と読むべきです。

## 4. 4 つの壁

### 壁 1: リンカとライブラリの世代差

純正の .so は **Android 4.1（2012年）** 向けにビルドされています。Android 9 で読ませると:

- **リンカ名前空間**（Android 7 以降）が、システムライブラリへの直接リンクを拒否します
- `libutils.so` / `libbinder.so` / `libcutils.so` の ABI が JB 時代とは変わっています
- `libstdc++` / STLport 依存（元ツリーに `android_external_stlport` があるのは、この手の互換のため）
- Android 8 以降の **Treble** による `/vendor` 分離

**回避策**: `/system/lib` に JB 時代の互換ライブラリを同梱し、
shim（`libsamsung_symbols` のような互換シンボル層）を用意する。
d2att-unified に `libsamsung_symbols` があるのは、まさにこれをやっているからです。

### 壁 2: アプリの API レベル

純正ワンセグアプリは API 16（4.1）想定です。Android 9 では:

- 実行時パーミッション（API 23〜）を知らないので、権限が下りない
- 非 SDK インターフェース制限（API 28〜）で内部 API 呼び出しが弾かれる
- `targetSdkVersion` が低すぎると、そもそも起動を拒否されることがある

**回避策**: apk の再署名と `targetSdkVersion` の書き換え、
あるいは `/dev/isdbt` を直接叩く**アプリの自作**。

### 壁 3: SELinux

`/dev/isdbt` へのアクセスには SELinux のラベルとルールが要ります。

なお d2att-unified の `BoardConfig.mk` は
`BOARD_KERNEL_CMDLINE += androidboot.selinux=permissive` で
**SELinux を permissive で動かしています**（`BOARD_SEPOLICY_DIRS` もコメントアウト済み）。
移植の初期段階ではこれが有利に働きます（ポリシー不足で止まらない）。
ただし**セキュリティ上は望ましくない**ので、動いた後に enforcing 化するのが筋です。

本リポジトリには `device/samsung/d2dcm/sepolicy/isdbt.te` を用意してあります。

### 壁 4: RMP（コンテンツ権利保護専用方式） ← 最大の壁

- 地上デジタル放送の DRM。**地上放送RMP管理センター**が運用。
- 2012年8月から順次導入、**2013年3月27日に全国運用開始**。
- B-CAS と同じ**3重鍵暗号方式**だが、物理カードではなく
  **受信機に「鍵データ」として埋め込む**ソフトウェア方式。

つまり **SC-06D の中のどこかに、この端末固有の鍵がある**ということです。
それが `/efs` にあるのか、隠しパーティションにあるのか、
NMI326 チップ内の OTP にあるのか、**実機を調べないとわかりません**。

- チップ内 OTP なら → 純正の .so さえ動けば鍵は勝手に読まれる（**移植の望みがある**）
- ファイルシステム上なら → そのファイルも一緒に移植すればよい（**望みがある**）
- 鍵の取得に純正カーネル/TrustZone の何かが要るなら → **厳しい**

`tools/oneseg-probe.sh` はこの切り分けのための情報を集めます。

## 5. 良い知らせ

ここまで壁の話ばかりでしたが、**下地はかなり整っています**。

1. **カーネルドライバが lineage-16.0 に残っている。**
   誰も消していません。`drivers/media/nmi326/` はそのままあります。

2. **d2dcm 用の defconfig が存在し、しかも有効になっている。**
   `arch/arm/configs/lineageos_d2dcm_defconfig`:
   ```
   CONFIG_MACH_M2_DCM=y
   CONFIG_ISDBT_NMI=y
   CONFIG_ISDBT_NMI_DEBUG=y
   CONFIG_SPI_QUP=y
   ```
   **`CONFIG_ISDBT_NMI=y`。** 誰かが SC-06D を意識して残しています。
   （参考: CM13 時代の `cyanogen_d2dcm_defconfig` では
   `# CONFIG_ISDBT_NMI is not set` と**無効**でした。lineage-16.0 で有効化されています。）

3. **ボードファイルも残っている。**
   `arch/arm/mach-msm/board-m2_dcm.c` に SPI 登録・GPIO 制御・電源シーケンスが揃っています。

4. **デバッグログが出る。**
   `CONFIG_ISDBT_NMI_DEBUG=y` なので、`dmesg | grep ISDBT` で
   `>ISDBT<` のプレフィックス付きログが見られます。**切り分けが楽になります。**

つまり **LineageOS 16.0 をビルドすれば、`/dev/isdbt` が出てきて、
電源 ON の ioctl まではその場で試せる**ということです。

具体的な手順は [`05-ワンセグ移植の手順.md`](05-ワンセグ移植の手順.md) にあります。
