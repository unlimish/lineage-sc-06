# 04. 書き込み手順と復旧

**この作業は端末を壊す可能性があります。自己責任で行ってください。**
特に SC-06D は 2012年発売で、部品も純正 ROM も入手性が下がっています。

---

## 0. 先にやること（省略不可）

### EFS のバックアップ

`/efs` には **IMEI と電波関連の校正データ**が入っています。
壊すと**通信できない端末になり、復旧できません**。

```bash
adb shell su -c 'dd if=/dev/block/platform/msm_sdcc.1/by-name/efs of=/sdcard/efs.img bs=4096'
adb pull /sdcard/efs.img
```

取れた `efs.img` は **PC 側の安全な場所に、複数箇所に**保存してください。
端末の中にだけ置いても意味がありません。

`/efs` は **RMP 鍵の在り処の候補でもあります**
（[`02-ワンセグの構造と壁.md`](02-ワンセグの構造と壁.md) 第4節）。ワンセグを狙うなら二重に重要です。

### 純正 ROM 全体のバックアップ

ワンセグ移植をするなら `/system` の中身が必要です。
[`tools/oneseg-probe.sh`](../tools/oneseg-probe.sh) が `/system/{lib,etc,framework,bin}` を
引っ張ってきますが、**それとは別に丸ごとのイメージも取っておく**ことを勧めます。

```bash
adb shell su -c 'dd if=/dev/block/platform/msm_sdcc.1/by-name/system of=/sdcard/system.img bs=4096'
adb pull /sdcard/system.img
```

`/sdcard` の空き容量に注意してください（1.5GB 前後必要）。

### 純正 ROM（Odin 用）の入手

**文鎮化したときの唯一の戻り道です。** 先に手元に置いてから始めてください。
SC-06D の最終ファームウェアは `SC06DOMBMF1`（Android 4.1.2）です。

### おサイフケータイの残高移行

FeliCa はカスタム ROM では動かないものと考えてください。
**移行手続きは、書き込む前に必ず済ませてください。**

---

## 1. ブートローダについて

SC-06D は docomo 版ですが、d2 系は**ブートローダのアンロック操作が不要**で、
Odin（Samsung のダウンロードモード）から書き込めます。
ただし書き込むと **Knox / カスタムバイナリカウンタが立ちます**（元には戻せません）。

---

## 2. ダウンロードモードに入る

1. 電源を切る
2. **音量下 + ホーム + 電源** を同時に長押し
3. 警告画面が出たら **音量上** で続行

---

## 3. カスタムリカバリ（TWRP）を焼く

Windows なら Odin、Linux なら Heimdall を使います。

```bash
# Linux / Heimdall
heimdall flash --RECOVERY twrp-d2dcm.img --no-reboot
```

**注意**: SC-06D 専用の TWRP イメージが必要です。d2att / d2lte 用の
イメージは**パーティション構成が違う可能性があり、そのままでは危険**です。
`oneseg-report/by-name.txt` で自分の端末の構成を確認してから選んでください。

manifest には TWRP のデバイスツリー（d2att 用）も含めてあるので、
自分でビルドするのが最も確実です。

---

## 4. リカバリで焼く

1. **音量上 + ホーム + 電源** でリカバリ起動
2. TWRP で **Backup** — 全パーティションのバックアップを取る（ここでもう一度）
3. **Wipe** → Advanced Wipe → `Dalvik / System / Data / Cache` にチェック
   （**Internal Storage と EFS にはチェックを入れない**）
4. `lineage-16.0-*-d2dcm.zip` を Install
5. 必要なら GApps も（Android 9 用 ARM の pico〜nano 推奨。この端末の容量では full は入りません）
6. Reboot System

初回起動は 5〜10 分かかることがあります。

---

## 5. 起動したら確認すること

```bash
adb shell getprop ro.build.version.release       # -> 9
adb shell getprop ro.product.device              # -> d2dcm

# ワンセグの入口が開いているか（これが本プロジェクトの最初の関門）
adb shell ls -l /dev/isdbt
adb shell 'dmesg | grep -i isdbt'
adb shell 'cat /proc/devices | grep 225'
```

`/dev/isdbt` が出てきて、`dmesg` に `>ISDBT<` のログがあれば、
**カーネル側は成功**です。[`05-ワンセグ移植の手順.md`](05-ワンセグ移植の手順.md) の
ステップ 2 に進めます。

---

## 6. 復旧

### 起動しない（ブートループ）

1. リカバリに入る（音量上 + ホーム + 電源）
2. TWRP の Restore で、手順 4-2 のバックアップを戻す

### リカバリにも入れない

1. ダウンロードモード（音量下 + ホーム + 電源）
2. Odin / Heimdall で純正 ROM を書き戻す

### ダウンロードモードにも入れない

ハードブリックです。JTAG などの物理的な手段が必要になり、
実質的には**修理不能**と考えてください。だからこそ手順 0 が重要です。

### 通信できない（IMEI が消えた / null になった）

`efs.img` を書き戻します。

```bash
adb push efs.img /sdcard/efs.img
adb shell su -c 'dd if=/sdcard/efs.img of=/dev/block/platform/msm_sdcc.1/by-name/efs bs=4096'
```

**バックアップが無い場合は復旧できません。**
